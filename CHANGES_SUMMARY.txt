1. OVERVIEW OF RECENT CHANGES
--------------------------------------------------------------------------------
This document outlines the changes made to CollabSphere (Intelligent Document
Management System) to implement user authentication with PostgreSQL, per-user
isolated storage directories, a non-blocking fast upload workflow, and a 
dedicated login/signup frontend interface.

--------------------------------------------------------------------------------
2. BACKEND IMPLEMENTATION (GOLANG ECHO + POSTGRESQL + JWT)
--------------------------------------------------------------------------------
A. PostgreSQL Database & User Store
   - File: backend/idms/database/postgres.go
   - Integrated PostgreSQL driver (github.com/lib/pq).
   - Auto-initializes the "users" table upon startup if it does not exist:
       CREATE TABLE IF NOT EXISTS users (
           id SERIAL PRIMARY KEY,
           username VARCHAR(50) UNIQUE NOT NULL,
           password_hash VARCHAR(255) NOT NULL,
           created_at TIMESTAMP DEFAULT NOW()
       );
   - Password Hashing: Uses bcrypt (golang.org/x/crypto/bcrypt) with default cost.
   - Authentication check: AuthenticateUser() validates username & password.

B. JWT Middleware & Protected Routes
   - File: backend/idms/middleware/auth.go
   - Validates "Authorization: Bearer <token>" headers.
   - Checks HMAC SHA256 signature using JWT_SECRET from environment.
   - Extracts the authenticated "username" and injects it into Echo context (c.Set("username", username)).
   - Rejects unauthenticated or expired requests with HTTP 401.

C. Auth Handlers (Signup & Login)
   - File: backend/idms/handler/auth-handler.go
   - POST /api/signup: Validates input, hashes password, saves user in PostgreSQL.
   - POST /api/login: Verifies credentials and generates a 24-hour signed JWT token.

D. Per-User Folder Isolation & Security
   - File: backend/idms/handler/file-handler.go
   - Folder Prefix: Upload keys are forced to:
       "<username>/<timestamp>_<filename>"
   - File Listing: GET /api/files automatically restricts the MinIO listing
     prefix to "<username>/" so users cannot view files of other accounts.
   - Access Control (ownsKey helper):
     GET /api/download-url, GET /api/file-info, POST /api/move-file, and
     DELETE /api/file verify that the requested file key begins with "<username>/".
     Unauthorized attempts return HTTP 403 Forbidden.
   - File: backend/idms/handler/processing-handler.go
     Updated to use the authenticated JWT username for file processing.

E. Environment Configuration
   - File: backend/.env
   - Added POSTGRES_URL:
     postgres://priyanshu@127.0.0.1:5432/postgres?sslmode=disable
     (or if you create the postgres user: postgres://postgres:postgres@localhost:5432/idms?sslmode=disable)
   - Added JWT_SECRET:
     collabsphere-jwt-secret-change-in-production

3. FRONTEND IMPLEMENTATION (NEXT.JS 16 + REACT 19 + TAILWIND)
--------------------------------------------------------------------------------
A. Global Authentication Context
   - File: frontend/app/app/context/AuthContext.js
   - Maintains token and user state.
   - Persists session in browser localStorage ("idms_token", "idms_user").
   - Provides authFetch() wrapper that automatically includes the Bearer token
     and logs out / redirects on HTTP 401.
   - Root Layout wrapped in <AuthProvider> (frontend/app/app/layout.js).

B. Login & Registration Page
   - File: frontend/app/app/login/page.js
   - Modern tabbed interface allowing users to both "Sign In" and "Create Account".
   - Matches the IDMS branding (amber/zinc theme).
   - Provides input validation and error feedback.

C. Dashboard Page (File Explorer)
   - File: frontend/app/app/page.js
   - Route protected: Redirects to /login if unauthenticated.
   - Lists only the authenticated user's files from temp and main buckets.
   - Displays user folder status (/<username>) and file metadata (size, type, icons).

D. Fast / Non-Blocking Upload Page
   - File: frontend/app/app/upload/page.js
   - Route protected: Redirects to /login if unauthenticated.
   - Generates presigned URL from authenticated backend.
   - Uploads file directly to MinIO temporary bucket.
   - NON-BLOCKING BEHAVIOR:
     Once the file reaches the temp bucket, the UI immediately displays:
     "File uploaded to temp storage! Processing in background."
     The processing request is triggered asynchronously in the background so
     the user never has to wait for ClamAV / Tika / AI pipeline completion.

E. Sidebar Component
   - File: frontend/app/app/components/Sidebar.js
   - Highlights current active navigation.
   - Displays currently logged-in username badge with avatar.
   - Provides a one-click "Sign Out" button.

5. HOW TO RUN THE PROJECT
--------------------------------------------------------------------------------
1. Start PostgreSQL (e.g., via Docker or local service):
   docker run --name idms-postgres -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=idms -p 5432:5432 -d postgres

2. Start the Go Echo Backend (Port 8080):
   cd backend/idms
   go run main.go

3. Start the Next.js Frontend (Port 3000):
   cd frontend/app
   yarn dev

4. Open in browser:
   http://localhost:3000 -> Redirects to /login
   Create an account or sign in to start uploading files into your private folder!
